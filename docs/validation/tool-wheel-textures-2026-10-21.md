# Tool wheel texture repair

The editor-materialization pass damaged the wheel's procedural sprite assets. The persistence helper reserved an unnamed sprite's output path before saving its unnamed texture. Both chose the same path, and creating the sprite overwrote its texture. The empty asset name also produced extensionless files that became DefaultAssets after reimport. Earlier gameplay/input checks did not inspect these masks, so their passing results missed the appearance regression.

Restored the backdrop, center-hub and wedge masks using the wheel's existing generators and original parameters. The sprite files now have explicit `.asset` names and persistent texture dependencies. Their original GUIDs and Sprite fileIDs are retained, so the scene's existing references reconnect. No wheel geometry, fonts, icon assignments, input behavior or scene transforms were changed. The saved scene hash remains `A5850BBA3A16AF8086C46A1B9BB51FD638113938032371B86756ECE553FC3B7C`; current unsaved editor state was retained.

Fixed `EditableSceneVisualsSetup.PersistAssets` to save dependencies before choosing the parent's unique path and use the object type for unnamed assets. The repair and repeatable visual check live in `Assets/_Project/Editor/ToolWheelVisualRepair.cs`, available through **Tools > ViCSI > Scene Setup > Repair Tool Wheel Textures**.

Validation: three mask/texture checks pass after forced reimport, including center/band/corner alpha values.
